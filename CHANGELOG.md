# Changelog

All notable changes to this project are listed here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- The Dock's tiles show an icon above their label: each app's own launcher icon, read from the TV when Home opens without holding up its first frame (an app with no icon keeps its label alone), and the Launcher's own white line icons for Inputs and Settings. The tiles are clearer glass with a light edge, so Ember shows through more, and Ember is 9% darker on Home and the Idle Screen.

## [0.2.0] - 2026-10-23

### Changed

- The package lists, checked against the real Fuego 2K: entries `probe` found on the TV are marked confirmed; the Known-Bloat List gains the ACR ad-tracking app, the store demo, Google Feedback, the maker's e-manual, Google's screensaver (the Idle Screen replaces it), the USB media player and the preinstalled streaming apps the owner does not use; the Must-Keep List gains the TV stack HDMI depends on, the remote and Bluetooth pairing, the keyboard, WebView, the shell adb uses and the factory manager. Play Services is confirmed as the system updater. The evidence is in `docs/research/fuego-2k-packages.md`.
- The Launcher's own artwork is Ember, one gradient drawn in code (dark plum with purple, crimson and orange glows), in place of the four bundled pictures. Home shows it still, behind the frosted Dock; the Idle Screen shows it dimmed and slowly moving, its glows drifting on 40 to 90 second loops so nothing stands still. The owner's pictures in the Artwork Folder still win, with the same per-minute cross-fade on the Idle Screen.
- `apply` runs Debloat after setting the Idle Screen, and leaves a Known-Bloat package on while the TV's screensaver still points at it (Google's ambient mode when the Idle Screen did not take over), so the screensaver never points at a disabled app; the next `apply` disables it.

### Fixed

- Commands work when adb lists the TV twice (its address and the name adb's mDNS finds it under), which made every adb call fail with "more than one device" and showed as "Can't reach the TV". `connect` saves the TV's address beside the Snapshot, and each command talks to one device: `ANDROID_SERIAL` if set, else the saved address if listed, else the only device listed; with several listed and none of them saved, it asks to run `fuego connect` again.

## [0.1.0] - 2026-10-23

### Added

- The plan ([the spec](https://github.com/danajerban/fuego-os/issues/1)), the glossary, research notes, and the repository's community files.
- The four package lists (Keep, Must-Keep, Known-Bloat, Takeover Packages) under `lists/`, with a check that the Must-Keep List wins and no Takeover Package is on the Known-Bloat List or the Must-Keep List. The check skips comments and blank lines (also lines of only spaces) as the script does. The setup wizard is the first entry of `takeover.txt`, and the script reads it from there.
- The script's base (`script/fuego`): `check` names the tools the Mac is missing (`--build`: also JDK 17 and the SDK's android-34 platform and build-tools 36.0.0, what the Launcher's Android Gradle Plugin needs), `pair` and `connect` reach the TV over Wireless debugging, and an unreachable TV gets the Settings path to turn Wireless debugging back on ([TV setup steps](docs/tv-setup.md)). Script tests run against a fake TV with `script/tests/run`.
- `probe`: a read-only report of the TV's chip, RAM, storage and Android build, every package tagged with the lists it is on, a section flagging packages on none of the lists, and baseline measurements (available memory, Home Draw Time). Home Draw Time is taken once the Launcher is Home, without stopping any app: the Launcher's full-screen Inputs screen is opened (it is exported for this, and opened over adb it gets a task of its own), then Home reopened and timed against its budget (200 ms warm, 800 ms cold); before the Home Takeover, or when the TV gives no launch time, the line says "not measured" and why. An unreachable TV gets the Wireless debugging steps.
- The Launcher's base: a Home screen with a Dock of Netflix, YouTube, Stremio, Spotify and Settings tiles (missing apps hidden, Back does nothing), a manifest with no INTERNET permission, no receivers and no service except the Idle Screen's dream, and UI tests on an Android TV emulator.
- Contributor and agent guide (`CLAUDE.md`, with `AGENTS.md` pointing to it), decision records under `docs/adr/`, and glossary terms for the words the code and tickets now use.
- CI on every pull request and push to `main`: shellcheck 0.11.0, the script tests (also on macOS bash 3.2), the list check, the Launcher build and manifest checks (with a test that adding INTERNET fails the build), and the Launcher's UI tests on an Android TV API 34 emulator. Every action is pinned to a commit SHA.
- `apply` and `restore`: the first `apply` saves the Snapshot on the Mac (never overwritten), Debloat disables only the Known-Bloat List, animation scales go to 0.5, every write is read back, and a summary with before/after measurements is printed. `apply --dry-run` writes nothing anywhere. `restore` puts package states and animation scales back to the Snapshot. The measurements include the Launcher's memory.
- The Launcher's Inputs tile, between Spotify and Settings: it lists the TV's HDMI ports by the names set in TV Settings (hidden inputs left out, "No HDMI inputs found" when there are none), and choosing one switches the TV to it through the TV input player.
- The Launcher's look: full-screen artwork behind a frosted glass Dock, a new picture on every Home visit (the owner's JPEG and PNG pictures in name order when the Artwork Folder has any, else four bundled pictures), and a glass highlight and tile scale-up that follow D-pad focus in 120 ms. The blur and glass are adapted from CleanYourTV (MIT). `launcher/measure_budgets.sh` measures the cold and warm Home Draw Time and the memory against their budgets, and `docs/budgets.md` records each run (the first, on the `tv34` emulator, is within all three).
- The Home Takeover: `apply --launcher APK` installs the Launcher, makes it the Home activity as its own step, and only after the owner's yes to a Wi-Fi warning disables the Takeover Packages (setup wizard first); on a no, Home goes back to the app that held it before, read back. A Home press must then give the Launcher focus, or the takeover is rolled back; a TV that leaves the network gets the reconnect-and-`restore` steps. Every `apply` redoes the takeover if a TV update undid it. `restore` re-enables the Takeover Packages, hands Home back to the Snapshot's Home activity and uninstalls the Launcher, also when it is already gone. The first `apply` also saves a full copy of the TV's global, secure and system settings beside the Snapshot, a record for the owner that `restore` does not read. adb gets no input, so the owner's answers always reach the script.
- The Idle Screen: the Launcher's screensaver (`io.github.danajerban.fuegoos/.IdleScreen`), the Launcher's only service. It shows the same artwork as Home at half brightness and cross-fades to the next picture every minute; the first key press only wakes the TV. Home and the Idle Screen each keep their own place in the artwork, so neither skips the other's pictures. The manifest check fails the build on any other service.
- Releases: a tag `vX.Y.Z` publishes the signed Launcher APK, the script bundle and `SHA256SUMS` as a GitHub Release with grouped notes; a pull request that changes the Release workflow runs it as a dry run with a throwaway key. `apply` without `--launcher` installs the Launcher from the latest release, only if it matches its checksum. With the Launcher already on the TV, a rerun installs the latest release only when its version is newer, and leaves the Launcher as it is when the release is the same or older or can't be looked up; a refused update (another signing key, a lower versionCode) keeps the installed Launcher. The signing secrets and how to make and keep the key are in `docs/releasing.md`, and the README's Quick start has the steps from download to `restore`.
- The Check Step: after the Home Takeover, `apply` asks the owner, one at a time, to try casting, the HDMI inputs, Wi-Fi and the remote's Netflix and YouTube buttons, and records the answers in a `checks` file beside the Snapshot (which is never rewritten). Casting reported broken triggers the Casting Fallback: the setup wizard alone is re-enabled and read back, what has Home focus is reported and recorded, and the Stock Launcher stays disabled. Later runs leave the setup wizard on unless the owner says yes to disabling it again. The Check Step is skipped with `--skip-checks`, in a dry run, and when the input ends before any answer; the next `apply` then asks again.
- `apply` sets the Idle Screen as the TV's screensaver in place of Google's ambient mode and switches the screensaver on, read back; the idle timeout is never written. `apply --pictures FOLDER` copies the folder's JPEG and PNG pictures to the Launcher's Artwork Folder (starting the Launcher once if it has not made the folder yet), reads them back, and skips and lists every other file. `restore` puts the screensaver settings back to the Snapshot before uninstalling the Launcher. A dry run sets nothing and copies nothing.
